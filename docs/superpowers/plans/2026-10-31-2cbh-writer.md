# 2CBH Container-First Writer Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Write valid four-file ChessBase 2CBH databases from Brett sessions, preserving headers, names, moves, variations, Chess960 starts, and metadata, with annotations explicitly deferred.

**Architecture:** A new `src/twocbh/writer.rs` streams `.2cbh`, `.2cbg`, `.2cba`, and `.2lid` temporary files, then installs them with the same backup/rollback pattern as the classic CBH writer. It reuses the generated token table through a new inverse lookup and mirrors the reader's reverse-replay variation order exactly. The app makes 2CBH a writable save format and adds a confirmation dialog for replacement and annotation loss.

**Tech Stack:** Rust 2024 (MSRV 1.97), existing `domain::Game` tree, `cozy-chess` facade, `anyhow`, `memmap2` reader, egui app.

**Spec:** `docs/superpowers/specs/2026-10-31-2cbh-writer-design.md`

## Global Constraints

- MIT-only: no ChessBase code, binaries, tables, or token-table dumps.
- 2CBH sources stay read-only. The app must refuse to overwrite the open source or any of its six companion extensions.
- The writer emits 2CBH generation `0x26` only.
- Only standard chess and Chess960 starts are writable. Arbitrary FEN starts are rejected.
- Annotation loss is blocked by default in the library and must be confirmed in the app.
- Existing `TwoCbhFile` / `TwoCbhLibrary` public APIs and local real-file tests must keep working.
- Do not change large-database indexing caps, desktop integration, or packaging in this plan.
- Run `cargo test --all-targets`, `cargo clippy --all-targets -- -D warnings`, and `cargo fmt --all` before the final handoff.
- Commit after every task.

## Review Focus

- **Variation marker placement:** root alternatives and multiple branch points must attach variations to the correct parent, not one ply away. Pinned by `variation_markers_follow_the_replaced_move_and_round_trip` in Task 3.
- **Special-move token selection:** promotion, en passant, castling, and null moves must round-trip as the same move, not merely as a legal-looking move. Pinned by `special_moves_round_trip` in Task 3.
- **Chess960 classification:** a standard board with Chess960 castling must be written as kind 2 with the matching start id, and custom FENs must be rejected. Pinned by `chess960_start_and_castling_round_trip` and `rejects_custom_fen_and_unsupported_variants` in Task 3.
- **Name interning:** duplicate names with different FIDE ids must remain separate, UTF-8 must survive, and overlong names must fail rather than truncate. Pinned by `keeps_duplicate_names_with_distinct_fide_ids`, `preserves_utf8_names`, and `rejects_overlong_names` in Task 4.
- **Replacement and annotation loss:** replacing a database must remove stale `.2lcd`/`.2lgd` indexes, preserve unrelated files, and never silently drop comments/NAGs. Pinned by `removes_stale_derived_indexes_and_preserves_unrelated_files` in Task 2 and the annotation tests in Tasks 5 and 6.

```rust
fn normalize_stem(path: &Path) -> Result<PathBuf> {
    match path.extension().and_then(|ext| ext.to_str()) {
        Some(ext) if ext.eq_ignore_ascii_case("2cbh")
            || ext.eq_ignore_ascii_case("2cbg")
            || ext.eq_ignore_ascii_case("2cba")
```

Implement the framing helper with this exact padding rule:

```rust
fn frame_record(
    content: &[u8],
    terminator: [u8; 2],
    base_padding: u64,
    key: u64,
    offset: u64,
) -> Vec<u8> {
    let a = content.len() as u64;
    let b = base_padding
        + (8 - ((offset + 34 + a + base_padding) % 8)) % 8;
    let total = 34 + a + b;
    // magic (8), A (4), B (4), key (8), content (a),
    // terminator (2), zero padding (b), trailer (8)
    // ...
}
```

Use `base_padding = 98` for non-empty `.2cbg`, `194` for an empty `.2cbg`, and `194` for `.2cba`. The `.2cba` empty record content is `[0x00, 0x20, 0xff, 0xff]`, terminator `[0xff, 0x7f]`, key `0x0000_0000_7fff_ffff`.

Use a deterministic non-zero key for `.2cbg`:

```rust
fn record_key(index: u64, content: &[u8]) -> u64 {
    let mut hash = 0xcbf2_9ce4_8422_2325u64;
    for byte in index.to_le_bytes().iter().chain(content) {
        hash ^= u64::from(*byte);
        hash = hash.wrapping_mul(0x0000_0100_0000_01b3);
    }
    if hash == 0 { 1 } else { hash }
}
```

Implement `.2cbh` record 0 exactly as the design table: zeroed 192 bytes, `0x08 = 0x26`, `0x0a = 192u16.to_le_bytes()`, `0x0c = 0x0500u16.to_le_bytes()`, `0x10 = count.to_le_bytes()`.

Implement the `.2cbg` header (`u64 length`, `12u16`, `0x0500u16`), `.2cba` header (`u64 length`, `12u16`, `0u16`), and `.2lid` header from the design table using big-endian fields.

Implement `TwoCbhWriter` with four `File` handles or `BufWriter<File>` handles, a `TempGuard`, and `finish` that:

1. flushes and patches the `.2cbh` count, `.2cbg` length, `.2cba` length;
2. extends the `.2lid` file to `LID_FIRST + block_count * LID_STRIDE` and patches its header;
3. installs the staged files in the order `.2cbg`, `.2cba`, `.2lid`, `.2cbh` (header last);
4. backs up every existing file in `ALL_EXTENSIONS`, restores on failure, and deletes backups on success;
5. returns the report with the sum of the four core file sizes.

For this task, `block_count` is always `1`, `event_count` is `0`, and `add_game` does not exist yet. `write_database` accepts the game iterator but bails if it yields a game; Task 4 replaces that placeholder with `add_game`.

```rust
        .iter()
        .map(|&child| {
```

```rust
fn resolve_ply(before: &Chess, ply: &Ply) -> Result<Option<Move>> {
    if ply.uci == "0000" || ply.san == "--" {
        return Ok(None);
    }
    if let Ok(uci) = UciMove::from_ascii(ply.uci.as_bytes())
        && let Ok(mv) = uci.to_move(before)
        && !matches!(mv, Move::Put { .. })
    {
        return Ok(Some(mv));
    }
    if let Ok(san_plus) = SanPlus::from_ascii(ply.san.as_bytes())
        && let Ok(mv) = san_plus.san.to_move(before)
        && !matches!(mv, Move::Put { .. })
    {
        return Ok(Some(mv));
    }
    bail!(
        "cannot resolve move {} (UCI {}) in position {}",
        ply.san,
        ply.uci,
        Fen::from_position(before, EnPassantMode::Legal)
    )
}
```

Implement `encode_move` with these exact token rules:

- Null move: token `0`.
- `Move::Normal`:
  - `piece = role_code(role) | mover_color_bit`, where king=1, queen=2, knight=3, bishop=4, rook=5, pawn=6, and Black adds 8.
  - Non-capture: entry `[from, to, piece, 0, 0, 0, 0, 0]`.
  - Capture: entry `[from, to, piece, aux, 0, 0, 0, 0]`, where `aux = role_code(captured) | captured_color_bit`; the captured piece's color is the opposite of the mover's, so `captured_color_bit` is 8 when the mover is White and 0 when the mover is Black.
  - Promotion: entry `[from, to, piece, aux, to, to, role_code(promoted) | mover_color_bit, piece]`, where `aux` is the capture code above or 0. If the captured role is a pawn (unreachable in legal chess), use queen for `aux`.
- `Move::EnPassant`:
  - Stored squares are `file * 8 + rank`, so the captured pawn is one rank behind the destination: `captured = if mover is White { to - 1 } else { to + 1 }`.
  - `special7 = if mover is White { 14 } else { 6 }`.
  - Entry `[from, to, pawn | mover_color_bit, 0, captured, captured, 0, special7]`.
- `Move::Castle`:
  - The side is kingside when the castling rook's file is greater than the king's file, otherwise queenside. The mover's color comes from `before.turn()`.
  - Standard: king destination is the g/c file on the back rank, rook destination is the f/d file. Entry `[king_from, king_to, king | mover_color_bit, 0, rook_from, rook_to, 5 | mover_color_bit, 0]`.
  - Chess960: return `45_357 + u16::from(start_id) * 4 + color_offset + side_offset`, where white=0, black=2, queenside=0, kingside=1.
- `Move::Put`: bail.

For all non-Chess960-castling moves, call `table().token_for(entry)` and bail with the move and position if it returns `None`.

Implement the line encoder with this exact algorithm:

```rust
fn encode_line(
    game: &Game,
    start: usize,
    skip_first_branch: bool,
    chess960_start: Option<u16>,
    tokens: &mut Vec<u16>,
) -> Result<()> {
    let mut current = Some(start);
    let mut branch_points = Vec::new();
    let mut first = true;

    while let Some(node) = current {
        let parent = game.nodes[node].parent.context("move has no parent")?;
        let before = &game.nodes[parent].pos;
        let ply = game.nodes[node].mv.as_ref().context("node has no move")?;
        match resolve_ply(before, ply)? {
            Some(mv) => tokens.push(encode_move(before, mv, chess960_start)?),
            None => tokens.push(0),
        }

        if !(skip_first_branch && first) {
            let children = &game.nodes[parent].children;
            if children.len() > 1 && children[0] == node {
                for _ in 1..children.len() {
                    tokens.push(0xfffd);
                }
                branch_points.push(node);
            }
        }
        first = false;
        current = game.nodes[node].children.first().copied();
    }

    tokens.push(0xffff);
    for branch in branch_points.into_iter().rev() {
        let parent = game.nodes[branch].parent.context("branch has no parent")?;
        for &sibling in game.nodes[parent].children[1..].iter().rev() {
            encode_line(game, sibling, true, chess960_start, tokens)?;
        }
    }
    Ok(())
}
```

`encode_game_moves` calls `detect_start`, gets the first root child, and if there are no moves returns an empty token vector. Otherwise it calls `encode_line` with `skip_first_branch = false`. It returns `EncodedMoves { start_id, tokens }` with the final `0xffff` still present.

- `0x10..0x18`: `cba_offset` LE.
- `0x18/0x20/0x28/0x38`: white/black/event/source ids LE.
- `0x30`: `2u32` LE.
- `0x40..0x50`: `0xff`.

- `0x5c`: subround LE.
- `0x60/0x70`: Elo LE.
- `0x80`: `0xFC40 + start_id` for Chess960, else 0.
- `0x98`: game id LE.
- `0xb0`: beauty LE.
- `0xbc`: date LE.

`add_game`:

1. Calls `encode_game_moves` and wraps an error with the zero-based game index and the white/black names, so a bad ply names its game.
2. Builds `.2cbg` content: `kind` as a little-endian `u16` (`1` or `2`), then `0xfffc` for standard or `0xfffb`, start id, `0xfffc` for Chess960, then the encoded tokens. 3. Frames and writes the `.2cbg` record at the current offset. Use base padding 98 for non-empty move streams and 194 for an empty move stream.
4. Frames and writes the empty `.2cba` record at the current offset.
5. Interns white, black, event, and source and writes their `.2lid` records. Blank names are interned too.
6. Writes the `.2cbh` game record, passing `encoded.start_id` so the Chess960 marker at `0x80` matches the move record.
7. Increments `games` and updates offsets. Bail if `games.checked_add(1)` is greater than `u32::MAX` (the header count includes record 0).
