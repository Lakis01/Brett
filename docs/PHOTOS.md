# Player photos

Brett can show a small portrait beside each player at the board. Photos are an
optional local feature: **no photo data is part of Brett's source repository or
MIT-licensed distribution.**

## Where the photos come from

The photo pack is derived from the Scid project's `Player_photos.zip`, which
contains a single Scid Photo File (`Players.spf`):

- **Upstream archive:** `scid/PlayerData/Player_photos.zip` on SourceForge
  (<https://sourceforge.net/projects/scid/files/Player%20Data/>)
- **Derived pack:** `photos.bin`, generated by
  [`scripts/convert_spf.py`](../scripts/convert_spf.py)
- **Encoding:** each portrait is re-encoded as WebP; the pack is about 26 MB for
  roughly 14,000 players.

Brett does not download the archive, does not invoke Scid, and does not modify
the source archive.

## Redistribution status

The photo archive has **no explicit redistribution licence**. Scid's `COPYING`
file identifies database files as copyright Pascal Georges and asks users to
contact the respective authors before reusing those files. `Player_photos.zip`
itself contains only `Players.spf` and no licence text.

Therefore:

- Do **not** commit `assets/photos.bin` or any extracted portraits to this
  repository. The file is git-ignored.
- Do **not** bundle the pack in a release, installer, AppImage, or other binary
  distribution without written permission from the rights holders.
- Treat any local pack as personal data for personal use only.
- If permission is granted later, record it in
  [`THIRD_PARTY_NOTICES.md`](../THIRD_PARTY_NOTICES.md) before redistributing.

**Decision (2026-10-28):** request written redistribution permission from the
Scid authors, naming the derived BPF1/WebP pack, the intended distribution
channel, and the required attribution. Keep the pack local-only and out of all
release artefacts until a written answer is recorded here. A public-domain or
CC-licensed alternative source is acceptable only after its licence and
attribution requirements are audited.

The feature remains useful without a pack: when no pack is found, the photo
toggle is disabled and the board strips keep their normal compact layout.

## Building a local pack

Requirements: Python 3 with Pillow, a C compiler, and the libwebp development
headers (`libwebp-dev` on Debian/Ubuntu). The script builds a small helper
library and uses libwebp's highest-quality settings.

```sh
python3 scripts/convert_spf.py \
  "/path/to/Players.spf" \
  "$HOME/.local/share/brett/photos.bin"
```

The script validates the `photo "Name"` blocks, canonicalises player names,
sorts the index, and writes the `BPF1` pack. `scripts/libwebp_helper.so` is a
build artifact and is git-ignored.

## Where Brett looks for the pack

The first existing path wins:

1. `BRETT_PHOTOS` — an explicit file path.
2. `assets/photos.bin` in the current directory.
3. `assets/photos.bin` beside the source checkout (`CARGO_MANIFEST_DIR`).
4. `assets/photos.bin` or `photos.bin` beside the executable.
5. `~/Downloads/Brett Resources/Photos/photos.bin`.

A conventional user-data location is also fine:

```sh
mkdir -p ~/.local/share/brett
mv photos.bin ~/.local/share/brett/photos.bin
export BRETT_PHOTOS="$HOME/.local/share/brett/photos.bin"
```

## Pack format (`BPF1`)

```text
"BPF1" | u32 entry count | entries | WebP payloads
entry: u8 key length | key bytes | u32 offset | u32 length
```

- Keys use the same canonical identity as `players::player_key`: lowercase
  alphanumeric words, sorted, deduplicated, and joined with spaces. For example
  `Carlsen, Magnus` and `Magnus Carlsen` both become `carlsen magnus`.
- Entries are sorted by key for binary search.
- Offsets are absolute file positions. Brett memory-maps the file read-only and
  never writes to it.
- Each payload is a complete WebP image. Brett decodes it, downscales it to at
  most 160 × 160, and keeps only a small LRU cache of textures.

## UI behaviour

- Portraits appear beside each player in the board strips and in the Players
  tab. **Settings → Photo size** selects Small (38 px), Medium (54 px), or
  Large (72 px); the strip grows by the same amount plus 8 px of padding.
- The Players list keeps a fixed 34 px thumbnail so rows stay uniform. The
  selected-player header uses the configured size.
- Clicking any portrait — board strip, Players list, or player header — opens a
  standalone 240×300 view. The pack's usual source image is 80×100, so this is
  a deliberate enlargement, not additional detail.
- **Settings → Show player photos** hides or shows them. The setting defaults
  to on when a pack is available.
- Name lookup first tries the exact canonical key, then an accent-folded key,
  then a conservative short-name match. The last step lets `Capablanca, Jose`
  in the pack satisfy `José Raúl Capablanca` and `Gukesh D` satisfy `Gukesh
  Dommaraju`; it requires a matching surname and accounts for every pack token,
  so `Magnus Carlsen Jr` does not borrow Carlsen's portrait.
- Missing players simply keep the colour dot and the normal strip height.
- The pack is loaded once at startup. A corrupt or unreadable pack is ignored
  with a warning in the log; it never prevents a database from opening.
